# Phase 4 — UI Design Contract

> Visual and interaction contract for the QuestUI-styled Quran search page
> (`index.html` + `style.css` + `app.js` at repo root, deployed on GitHub Pages).
> Generated by `gsd-ui-researcher`; verified by `gsd-ui-checker`.

**Stack:** Vanilla HTML/CSS/JS — no framework, no build step, no runtime deps (D-26).
**Fonts:** Google Fonts `<link>` — Cinzel (headings) + Spectral (body) (D-23).
**Design system source:** QuestUI visual spec (https://designmd.ai/chef/questui) — hand-implemented in `style.css` as CSS custom properties. NOT loadable CSS.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | none (vanilla HTML/CSS/JS per D-26 — shadcn gate not applicable) |
| Preset | not applicable |
| Component library | none — hand-built HTML elements + CSS classes in `style.css` |
| Icon library | none (no icons; pure typography + color for visual language) |
| Heading font | Cinzel (Google Fonts), weights 600 only |
| Body font | Spectral (Google Fonts), weights 400 + 600 |
| Arabic font | Spectral fallback to system Arabic serif (`'Spectral', 'Amiri', 'Traditional Arabic', serif`) — Spectral renders Arabic acceptably; no separate Arabic web font loaded (keeps D-26's no-extra-deps ethos) |
| Font load strategy | `<link rel="preconnect">` + `<link rel="stylesheet">` with `display=swap` — page stays readable with serif fallback if Google Fonts is blocked |

```html
<link rel="preconnect" href="https://fonts.googleapis.com">
<link rel="preconnect" href="https://fonts.gstatic.com" crossorigin>
<link href="https://fonts.googleapis.com/css2?family=Cinzel:wght@600&family=Spectral:ital,wght@0,400;0,600;1,400&display=swap" rel="stylesheet">
```

CSS font stacks:
```css
--font-heading: 'Cinzel', 'Trajan Pro', 'Times New Roman', serif;
--font-body: 'Spectral', Georgia, 'Times New Roman', serif;
--font-arabic: 'Spectral', 'Amiri', 'Traditional Arabic', 'Noto Naskh Arabic', serif;
```

## Color Tokens

Full ramp. All values verified for contrast against the dominant `--bg` (see Accessibility Contract for ratios). **Never use pure white (`#FFFFFF`) or pure black (`#000000`)** — QuestUI mandates warm parchment and warm dark.

```css
:root {
  /* Surfaces (60% dominant + 30% secondary) */
  --bg:            #1A0F0A;  /* dark warm background — page background, dominant 60% */
  --surface:       #2C1A10;  /* card background — verse cards, hero panel, secondary 30% */
  --surface-raised:#3D2618;  /* search input bg, hover surface, focus container */
  --border:        #5C3A1F;  /* warm brown border — visible on --surface, not harsh */
  --border-subtle: #3D2618;  /* hairline divider inside cards (same as raised; only 1px) */

  /* Text */
  --text-primary:  #F5E6D3;  /* parchment — body, headings, verse text (never pure white) */
  --text-muted:    #B89A7A;  /* muted parchment — verse label, captions, secondary copy */

  /* Accents (10%) */
  --accent-gold:   #CA8A04;  /* primary accent — search focus, heading accents, <mark> bg, links */
  --accent-red:    #991B1B;  /* error state border/fill only — NEVER text on dark (contrast 1.8:1) */
  --accent-purple: #581C87;  /* decorative only — footer rule, hero flourish. NEVER text on dark */

  /* Highlight (<mark>) */
  --highlight-bg:  rgba(202, 138, 4, 0.30);  /* gold tint over card surface */
  --highlight-text: var(--text-primary);      /* parchment stays — no color change inside mark */

  /* Focus ring */
  --focus-ring:    0 0 0 3px rgba(202, 138, 4, 0.45);  /* gold halo, WCAG-visible */

  /* State overlays */
  --error-bg:      rgba(153, 27, 27, 0.18);  /* red tint over --surface for error card */
}
```

### 60/30/10 Split

| Role | Token | Hex | Applied to |
|------|-------|-----|------------|
| Dominant 60% | `--bg` | `#1A0F0A` | `<body>` background, page chrome |
| Secondary 30% | `--surface` | `#2C1A10` | Verse cards, hero panel, error card, search input container |
| Accent 10% | `--accent-gold` | `#CA8A04` | (see reserved-for list below) |

### Accent (`--accent-gold`) reserved for — NEVER "all interactive elements"

1. Search input focus state (border + focus ring)
2. Hero title text (`Al-Quran`) and section headings (`Ayat Pilihan`)
3. Verse card label color (the `Al-Baqarah (Lembu Betina / The Cow) • 2:255` line)
4. `<mark>` highlight background (matched terms in search results)
5. "Show more" + "Retry" button border (and on hover, button fill)
6. Spinner stroke during index load

### Semantic colors

| Role | Token | Notes |
|------|-------|-------|
| Error / destructive | `--accent-red` `#991B1B` | **Fill/border only.** Always paired with `--text-primary` on top (e.g. error card has red border + red-tinted bg + parchment text). Never used as text against `--bg` (contrast 1.8:1 fails). |
| Decorative | `--accent-purple` `#581C87` | Footer rule, optional hero flourish. Never text. |

**No destructive actions exist in this phase** (no delete, no overwrite, no clear-and-confirm). The closest is clearing the search input — handled inline without confirmation.

## Typography

**4 Latin sizes + 1 Arabic size (exception, justified by D-13 "Arabic larger").**
**2 weights: 400 (regular) + 600 (semibold).**

| Role | Font | Size (mobile / desktop) | Weight | Line Height | Letter Spacing | Usage |
|------|------|-------------------------|--------|-------------|----------------|-------|
| Display | Cinzel | 28px / 40px | 600 | 1.15 | 0.02em | Hero title (`Al-Quran`) only |
| Heading | Cinzel | 22px / 24px | 600 | 1.2 | 0.02em | Section headings (`Ayat Pilihan`), error card heading |
| Body | Spectral | 18px | 400 | 1.6 | normal | Malay verse text, hero subtitle, search input text, body copy |
| Label | Spectral | 14px | 600 | 1.4 | 0.04em (uppercase only when labelled as section heading) | Verse reference label, captions, result count, button text |
| Arabic *(exception)* | Spectral → Arabic serif fallback | 26px / 28px | 400 | 1.9 | normal | Arabic verse text (D-13: "larger than Malay") |

**Why an Arabic exception to the 4-size rule:** D-13 locks Arabic at "larger text" than Malay. Treating Arabic as a 5th Latin size would inflate the type scale; instead it is one dedicated token (`--arabic-size`) outside the Latin scale. Documented, justified, single-token.

CSS:
```css
:root {
  --text-display: clamp(28px, 5vw, 40px);   /* hero title */
  --text-heading: clamp(22px, 3vw, 24px);   /* section headings */
  --text-body: 18px;
  --text-label: 14px;
  --text-arabic: clamp(26px, 4vw, 28px);    /* verse Arabic */
}
```

**Typographic color rules:**
- Display + Heading text color: `--accent-gold` (Cinzel in gold is the QuestUI signature)
- Body text color: `--text-primary` (parchment)
- Label text color: `--accent-gold` for verse labels; `--text-muted` for captions/result counts
- Arabic text color: `--text-primary` (parchment — never muted; it's the primary content)

## Spacing Scale

All values are multiples of 4. Standard 8-point scale.

| Token | Value | Usage in this phase |
|-------|-------|----------------------|
| xs | 4px | `<mark>` padding (inline), inline icon gaps (none currently) |
| sm | 8px | Card border-radius, label-to-Arabic gap inside verse card (8px), spinner-to-text gap |
| md | 16px | Default element gap, mobile result grid gap, verse card Arabic-to-Malay gap, hero subtitle margin-top |
| lg | 24px | Section padding, desktop result grid gap, verse card padding, hero horizontal padding |
| xl | 32px | Hero vertical padding (mobile), section break between hero and results |
| 2xl | 48px | Hero vertical padding (desktop), major section breaks |
| 3xl | 64px | (Reserved — not used in v1; available for future page sections) |

### Exceptions (justified — touch targets and rhythm)

| Element | Value | Why |
|---------|-------|-----|
| Search input height | **56px** | ≥44px touch target (WCAG 2.5.5) + comfortable thumb typing |
| Search input padding-y | 12px | Optical centering of 18px Spectral text in 56px height (56 − 12×2 = 32px text lane, comfortably fits the 18px/line-height-1 line) |
| "Show more" / "Retry" button height | **44px** | WCAG 2.5.5 min touch target |
| "Show more" / "Retry" button padding-x | 24px | Comfortable click area beyond label |
| Verse card Arabic margin-bottom | 12px | Tighter than `md` so Arabic + Malay read as a unit |
| Page horizontal padding (mobile) | 16px | Standard mobile gutter |
| Page horizontal padding (desktop) | 32px | Wider margins on large screens |
| Result grid max-width | 1100px | Caps line length on ultra-wide screens |

## Breakpoints (D-24)

Two layouts only. Mobile-first.

| Breakpoint | Min-width | Layout |
|------------|-----------|--------|
| Mobile (default) | — | Single column. Hero, search, featured cards, results all full-width. |
| Desktop | `min-width: 768px` | Result grid becomes 2 columns. Hero + search remain centered single-column (max-width caps). |

```css
/* Mobile-first default */
.results-grid { display: flex; flex-direction: column; gap: 16px; }

/* Desktop */
@media (min-width: 768px) {
  .results-grid { display: grid; grid-template-columns: repeat(2, 1fr); gap: 24px; }
}
```

Page chrome centered container (all viewports):
```css
.container { max-width: 1100px; margin: 0 auto; padding: 0 16px; }
@media (min-width: 768px) { .container { padding: 0 32px; } }
```

### 2. Search Input (`.search` + `#search-input`)

**Anatomy:**
```
┌──────────────────────────────────────────────────┐
│  Cari ayat Al-Quran… (contoh: rahmat, بسم)      │  ← input, 56px tall
```

**Spec:**
- Container `.search`: full-width mobile, `max-width: 720px; margin: 0 auto` desktop, padding `0 16px`
- `#search-input`:
  - `width: 100%`, `height: 56px`
  - `padding: 12px 16px`
  - `background: var(--surface-raised)`
  - `border: 1px solid var(--border)`
  - `border-radius: 8px`

```

│                                                  │
│                            ٱللَّهُ لَآ إِلَٰهَ إِلَّا هُوَ │  ← .verse-arabic (Arabic, RTL, right-aligned)
│                            ٱلْحَىُّ ٱلْقَيُّومُ            │
│                                                  │
│ Allah, tiada Tuhan melainkan Dia, Yang Maha     │  ← .verse-malay (Body, LTR)
│ Hidup; Yang terus-menerus menguruskan…          │
└──────────────────────────────────────────────────┘
```

**Spec:**
- `.verse-card`:
  - `background: var(--surface)`

  - `border-radius: 8px`

  - `box-shadow: 0 2px 8px rgba(0, 0, 0, 0.4)` (subtle elevation)
  - `transition: border-color 200ms ease`
- `.verse-label`:
  - Spectral 600, `var(--text-label)`, color `--accent-gold`
  - `margin-bottom: 16px`
  - `text-transform: none` (proper nouns; do not uppercase)
- `.verse-arabic`:
  - `font: 400 var(--text-arabic)/1.9 var(--font-arabic)`
  - `color: var(--text-primary)`
  - `direction: rtl; text-align: right; unicode-bidi: isolate;` (D-19 per-line)
  - `lang="ar"` attribute on the `<p>` (set via JS)
  - `margin: 0 0 12px 0`
- `.verse-malay`:
  - `font: 400 var(--text-body)/1.6 var(--font-body)`
  - `color: var(--text-primary)`
  - `direction: ltr; text-align: left;` (explicit — D-19)
  - `margin: 0`
- `<mark>` inside either paragraph:
  - `background: var(--highlight-bg); color: var(--highlight-text);`

  - No `text-decoration` (gold bg is enough emphasis)

**States (desktop only — no hover on touch):**
- `:hover` — `border-color: var(--accent-gold);` (200ms ease; no transform, no shadow change — subtle)
- Focusable? **No** — verse cards are display-only in v1 (no click handler; deep-linking is deferred per CONTEXT.md `<deferred>`). No focus ring.

**Rendering rule (security — RESEARCH.md Pitfall 4/7):** Build with `document.createElement` + `textContent`. **Never** `innerHTML`. Always render `verse.arabic` / `verse.malay` originals (never the folded mirror).

Triggered by D-02 while `api/search.json` (~3MB / ~830KB gzip) downloads.

**Anatomy:**
```

     Memuatkan indeks…
Memuatkan 6,236 ayat. Sila tunggu sebentar.
```

**Spec:**
- Centered card replacing hero+featured area
- `.loading-card`: `background: var(--surface); border: 1px solid var(--border); border-radius: 8px; padding: 48px 24px; text-align: center; max-width: 480px; margin: 48px auto;`

### 7. No-Results / Fuzzy Suggestions State (`.no-results`) — D-18

Triggered when search returns 0 verses. Fuzzy suggestions computed lazily on first occurrence (RESEARCH.md Pattern 3).

**Anatomy:**
```
        Tiada padanan ditemui
Tiada ayat yang mengandungi "xyzabc".
         Mungkin maksud anda:
   ┌────────────────────────────┐
   │ [card] closest match 1      │  ← up to 5 fuzzy verse cards
   │ [card] closest match 2      │
   │ …                           │
   └────────────────────────────┘
```

**Spec:**
- `.no-results-card`: `background: var(--surface); border: 1px solid var(--border); border-radius: 8px; padding: 48px 24px; text-align: center;`
- `.no-results-title`: Cinzel 600 `var(--text-heading)`, color `--accent-gold`, `margin-bottom: 16px`
- `.no-results-body`: Spectral 400 `var(--text-body)`, color `--text-primary`, `margin-bottom: 32px`. The failed query is shown verbatim inside `<strong>` (built via `textContent`, not interpolated).
- `.no-results-suggestions-label`: Spectral 600 `var(--text-label)`, color `--text-muted`, `text-transform: uppercase; letter-spacing: 0.04em; margin-bottom: 16px;`
- Suggestions: same `.verse-card` component, rendered in a single-column grid (even on desktop — keeps the focus narrow), capped at **5 cards**.

**Fuzzy threshold (OpenCode discretion, locked here):**
- Edit distance ≤ 1 for query words ≤ 4 chars
- Edit distance ≤ 2 for query words > 4 chars
- Show top 5 by smallest distance, ties broken by ascending verse id
- If no candidates within threshold → omit the suggestions block entirely; show only `Tiada padanan ditemui` + body (honest empty)

**Rule: `--accent-red` and `--accent-purple` are NEVER used as text against `--bg` or `--surface`.** They appear only as borders, fills (with parchment text on top), or decorative rules.

### Focus management

- All interactive elements (`#search-input`, `.show-more`, `.retry-button`) get `:focus-visible { outline: none; box-shadow: var(--focus-ring); }` — gold 3px halo, WCAG-visible on every background.
- Focus order is DOM order: `#search-input` → (results) → `.show-more` (when present) → `.retry-button` (only in error state).
- `tabindex` is **not** set anywhere — rely on native semantics.

### RTL handling (D-19)

- Page chrome stays LTR: `<html lang="ms">` (no `dir` attribute on `<html>` or `<body>`).
- Each Arabic paragraph gets `dir="rtl"` AND `lang="ar"` set via JS on the `<p class="verse-arabic">` element. Use `el.setAttribute('dir', 'rtl')` and `el.setAttribute('lang', 'ar')`.
- Arabic paragraphs use `text-align: right` explicitly (so the bidi algorithm doesn't second-guess the first line).
- Malay paragraphs explicitly `direction: ltr; text-align: left;` so an Arabic-heavy page doesn't bleed RTL into Malay.
- `<mark>` works correctly inside both directions — `unicode-bidi: isolate` on `.verse-arabic` keeps the highlighted span contained.
