    ```yaml
    name: Deploy static content to Pages

    on:
      push:
        branches: [main]
      workflow_dispatch:

    permissions:
      contents: read
      pages: write
      id-token: write

    concurrency:
      group: pages
      cancel-in-progress: true

    jobs:
      build:
        runs-on: ubuntu-latest
        steps:
          - name: Checkout
            uses: actions/checkout@v4
          - name: Set up Python
            uses: actions/setup-python@v5
            with:
              python-version: '3.12'
          - name: Configure Pages
            uses: actions/configure-pages@v5
          - name: Unpack database
            run: gunzip -k quran.db.gz
          - name: Generate API
            run: python3 generate_json_api.py --generate
          - name: Validate API
            run: python3 generate_json_api.py --validate
          - name: Stage site
            run: mkdir -p _site && cp -r api _site/
          - name: Upload artifact
            uses: actions/upload-pages-artifact@v3
            with:
              path: _site
      deploy:
        environment:
          name: github-pages
          url: ${{ steps.deployment.outputs.page_url }}
        runs-on: ubuntu-latest
        needs: build
        steps:
          - name: Deploy to GitHub Pages
            id: deployment
            uses: actions/deploy-pages@v5
    ```

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| GitHub Actions runner → repo contents | The workflow executes repository code (`generate_json_api.py`) and data (`quran.db.gz`) on a GitHub-hosted runner; only `main`-branch content reaches it (D-08 triggers) |
| build job → Pages artifact | The build job's `--validate` gate (D-09) is the only integrity check between generated content and the published artifact |
| deploy job → GitHub Pages CDN | `deploy-pages` publishes the uploaded `github-pages` artifact to a PUBLIC CDN; content is readable by anyone (Pages sites are public by default) |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-01 | Tampering | build job → artifact (unvalidated/partial content deployed) | mitigate | `--validate` runs as a standalone step (exit 0/1); a non-zero exit fails the `build` job and `needs: build` prevents the deploy job from starting (D-09). Only `main` pushes trigger the workflow (D-08), so unreviewed PR content never deploys. |
| T-03-02 | Elevation of Privilege | GITHUB_TOKEN misuse from a compromised step | mitigate | Least-privilege permissions exactly per D-04: `contents: read` (cannot write repo), `pages: write` (can only create Pages deployments), `id-token: write` (OIDC for deploy-pages). No secrets in the workflow. |
| T-03-03 | Spoofing | Unauthorized workflow_dispatch / non-main ref deployment | mitigate | `workflow_dispatch` requires write permission to the repo by definition; `push` is restricted to `branches: [main]` (D-08). `deploy-pages` validates OIDC claims (branch/ref) before creating a deployment. |
| T-03-04 | Information Disclosure | Sensitive repo files published to public CDN | mitigate | D-05/D-06 staging: only `_site/` (containing just `api/`) is uploaded via `upload-pages-artifact path: _site`. The 62MB `quran.db.gz`, README, scripts, and source code never enter the artifact. |
| T-03-05 | Denial of Service | Deploy queue pileup / stale deploys racing | mitigate | D-10 concurrency group `group: pages` + `cancel-in-progress: true` — rapid successive pushes cancel in-progress runs and only the latest deploys. Site size 3.5MB is trivially under the 1GB Pages limit. |
</threat_model>
